# Impact Analysis explorers use `run_subagent`, not `ToolLoopAgent`

The Impact Analysis Agent's GitHub and Atlassian explorers are implemented as new `SUBAGENTS` registry entries invoked through the existing `run_subagent` tool, rather than as `ai@6`'s first-class `ToolLoopAgent` class. `ToolLoopAgent` is the SDK-native way to build a "subagent as a tool" and was seriously considered — it's directly supported by the pinned `ai` version — but `run_subagent`/`SUBAGENTS` already gives every property Impact Analysis needs (a fresh `generateText` call, no parent message history, a whitelisted tool set, a single distilled string returned to the caller), and it's the only tool-restriction/context-isolation mechanism that exists anywhere in the codebase today. Introducing `ToolLoopAgent` alongside it would mean two parallel, differently-shaped subagent mechanisms for the same problem. `ToolLoopAgent` remains the natural choice if a future subagent needs something `run_subagent` can't do (e.g. its own model/step-limit override per call site, or streaming back to the parent).
