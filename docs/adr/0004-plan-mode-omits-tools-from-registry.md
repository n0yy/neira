# Plan Mode omits mutating tools from the registry, rather than auto-denying them

Permission Mode's Plan value stops the AI from mutating anything. The alternative to consider was leaving every mutating tool (`write_file`, `create_directory`, `edit`, `multi_edit`, `bash_run`, `bash_background`, managed-agent tools) in the registry as always-present but auto-denied at the `needsApproval` gate, the same mechanism Auto and Accept Edits already use to auto-approve. We rejected that: an always-present-but-denied tool still costs a call attempt, a denial round-trip, and a chance for the model to quietly retry or route around the denial instead of switching to planning language. It also means the model's own understanding of what it can do (from the tool list it was given) diverges from what it's actually allowed to do, which is exactly the kind of mismatch that produces confused or evasive behavior.

Instead, `buildTools(ctx)` omits every mutating tool from the registry entirely when the conversation's Permission Mode is Plan, leaving only the always-available read-only tools (`read_file`, `list_directory`, `grep`, `glob`) plus the non-mutating `todo_write`. The model never sees the mutating tools as callable, so there's no gap between what it's told it can do and what it can actually do.

The trade-off: this makes Plan Mode a hard partition on `buildTools(ctx)`'s output rather than a per-call runtime check, so any new mutating tool added later must remember to declare itself as such (already true today, since `needsApproval: true` is the existing signal `buildTools` reads) or it will silently execute unattended in Plan Mode. This is the same risk Auto mode already carries for the same reason, so it isn't new surface area, just an existing one this decision leans on again.
