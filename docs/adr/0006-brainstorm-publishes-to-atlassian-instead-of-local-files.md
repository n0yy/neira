# Brainstorm publishes specs/ADRs/tickets to Atlassian instead of local files

The Brainstorm agent used to write every artifact it produced (`spec.md`, ticket files, ADRs) to disk only — `.scratch/<feature-slug>/` and `docs/adr/` — and explicitly never published to a tracker. We're replacing that entirely: Brainstorm now writes specs and ADRs directly to Confluence and tickets directly to Jira, via two new tools (`push_confluence`, `push_jira`), and stops writing those artifacts locally. `NEIRA.md` maintenance is unaffected. This only changes the Brainstorm agent — `docs/adr/` writes elsewhere in this repo (e.g. via the domain-modeling skill, outside the Brainstorm persona) and the separate `to-spec`/`to-tickets` skill flow (which already publishes to GitHub) are untouched.

We considered keeping the local-only behavior and adding push as a separate, later, manual step reading from the existing files on disk. We rejected it: a local draft plus a separate push step means two sources of truth that can silently drift (the file gets hand-edited after the push, or pushed twice by accident), for a feature whose entire point is to hand the artifact to Confluence/Jira as the record of truth. Writing directly, once, at the end of the interview (after the user's explicit confirmation) avoids that split.

To decide create-vs-update without inventing new state, `push_confluence`/`push_jira` search Confluence/Jira by a predictable title (`<feature-slug>` for specs, `ADR-<NNNN>: <slug>` for ADRs, `[<feature-slug>] <ticket title>` for tickets) using the existing read-only `searchCql`/`searchJql` client functions before writing, rather than persisting a feature-slug → page-ID/issue-key mapping anywhere. This trades a search round-trip for not having a mapping that can desync from what's actually in Atlassian.

This is also the first tool restriction scoped to a built-in Agent's *identity* rather than to a Subagent's context isolation — every built-in Agent (Coder, Code Reviewer, Impact Analysis, Brainstorm) previously saw the same full tool registry, with only `Subagent` types (`explore`, `github-explorer`, etc.) getting a restricted whitelist. Brainstorm now declares its own whitelist (`read_file`, `list_directory`, `grep`, `glob`, `write_file`, `edit`, `run_subagent`, `push_confluence`, `push_jira`) so it can't call `write_file`/`bash_run`/etc. to write code — previously true only by prompt instruction, not enforced. Every other built-in Agent keeps unrestricted access by default; this is opt-in per agent, not a new default constraint.
